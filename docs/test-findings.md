# 实机测试问题记录

更新日期：2026-09-21

本文档记录 StarCore V2 与 StarBridge Python SDK 的实机测试结果。“已解决”表示修复已进入代码；“待验证”表示还需要更多硬件样本或长时间测试。

| 编号 | 问题 | 实测现象 | 状态 | 处理 |
|---|---|---|---|---|
| SB-001 | CH9102 串口无法自动识别 | StarCore V2 在 `VID:PID=1A86:55D4` 时只能手动指定 `COM4` | 4.3.0 已解决 | 增加 CH9102 VID/PID 和 `ch910`/`wch.cn` 描述匹配，并增加自动发现测试。 |
| SB-002 | 首次烧录过程缺少反馈 | 程序长时间无输出，用户无法判断是否卡住 | 4.3.0 已解决 | 显示 StarBridge/SDK/固件版本、目标板、串口和单行进度条。 |
| SB-003 | 错误信息只有命令号和状态码 | DHT11 和超声波失败时均显示 `status 5` | 4.3.0 已缓解 | SDK 按命令输出中文原因和接线/参数解决建议，同时保留技术状态码便于排查。 |
| SB-004 | DHT11 接 P2 无法读取 | P2 是 GPIO35，只能输入，无法发出 DHT11 起始信号 | 已确认为硬件限制 | 示例改用 P1；错误信息明确禁用 P2/P3/P4/P10。 |
| SB-005 | 超声波近距离时程序退出 | 手贴近探头时没有 ECHO，返回 `status 5` | 已确认为传感器盲区 | 示例捕获 `BoardCommandError` 并显示“过近或无回波”，循环不再退出。 |
| SB-006 | 中文工作区路径导致 ESP32 链接失败 | `ld.exe` 无法在中文路径下创建 ELF | 4.2.0 已解决 | 构建和验证中间文件改用 `%LOCALAPPDATA%\StarBridge` 英文路径。 |

## 尚未完全解决

1. 固件协议中的 `BAD_ARGUMENT` 同时表示引脚无效、传感器无数据和外设执行失败。SDK 4.3.0 能给出针对性建议，但要精确区分“无回波”“校验失败”“引脚不支持”，仍需在下一个协议/固件版本增加更细状态码。
2. P6 与板载蜂鸣器共用 GPIO16，P7 与板载 WS2812B 共用 GPIO17。超声波在 P6/P7 已取得有效距离，但仍需要对不同型号模块、长时间运行和外部供电进行稳定性测试。
3. Windows 通常可自动安装 CP210x/CH9102 驱动，但无网或裁剪系统可能仍需要手动安装 USB 串口驱动。wheel 不应静默安装系统驱动。

## 下一轮实机回归

- CP210x 和 CH9102 各至少一块 StarCore V2，验证零参数自动发现。
- 分别测试 DHT11 断线、反接、连续读取和数小时稳定性。
- 对超声波进行 2 cm–400 cm、无目标、吸音材料和斜面测试。
- 验证 OLED、DHT11、超声波同时运行 2 小时。
- 验证烧录成功、串口占用、USB 中断和错误板型时的进度与引导信息。
